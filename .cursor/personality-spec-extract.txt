# Cursor Prompt — DOST Expanded Onboarding: Personality Profile

## Overview

You are extending DOST's onboarding flow to collect a richer personality profile — Enneagram (mini-quiz), Numerology (auto-computed from birthdate, zero extra input), TCM Element (2 dropdowns), and an optional MBTI self-report field. All of this is grounded in `Body_composition-AEA_profiling_with_coding.docx`. Every module is skippable — onboarding can be completed with just the existing Dosha step if the user wants. The resulting profile is stored server-side and injected as context into DOST's system prompt so responses are personalized.

DOST is an Expo app (Dev Client + EAS Build), React Native, TypeScript, Supabase backend. Existing onboarding already collects: name, intention, birth date, place of birth, Dosha tendency. This build adds new steps to that existing flow — it does not replace it.

## What's being added, in plain terms

1. **Enneagram** — a short 8-question quiz (not 27+ question professional tests) that gives a reasonable-confidence primary type. If the user already knows their type, they can just self-report it instead of taking the quiz.
2. **Numerology (Life Path Number)** — computed automatically from the birthdate already collected. Zero new questions. Just a calculation + a short reveal screen.
3. **TCM Element** — 2 simple dropdown questions (dominant emotional state, preferred climate) mapped to one of 5 elements.
4. **MBTI (optional, self-report only)** — a single text field: "If you know your Myers-Briggs type, share it here" with examples. No quiz built for this — only for users who already know it.

All four join the existing Dosha in a `personality_profile` table, and the whole profile gets serialized into DOST's system prompt as personalization context.

### STEP 1 — Create the personality_profile table

In Supabase SQL Editor:

```sql
create table if not exists personality_profile (
  user_id uuid primary key references auth.users(id) on delete cascade,

  -- Existing (already collected elsewhere — this table centralizes it)
  dosha_body text,
  dosha_mind text,

  -- Enneagram
  enneagram_type int check (enneagram_type between 1 and 9),
  enneagram_source text check (enneagram_source in ('quiz', 'self_report')),

  -- Numerology (computed, not user-entered)
  life_path_number int,

  -- TCM
  tcm_element text check (tcm_element in ('Wood', 'Fire', 'Earth', 'Metal', 'Water')),
  tcm_emotional_state text,
  tcm_climate_preference text,

  -- MBTI (optional self-report)
  mbti_type text,

  -- Tracking what's been completed vs skipped
  completed_modules text[] default '{}',
  skipped_modules text[] default '{}',

  updated_at timestamptz default now()
);

alter table personality_profile enable row level security;
create policy "own profile read" on personality_profile for select using (auth.uid() = user_id);
create policy "own profile insert" on personality_profile for insert with check (auth.uid() = user_id);
create policy "own profile update" on personality_profile for update using (auth.uid() = user_id);
```

Explain to the user: this is a single-row-per-user table (unlike `message_emotions` which has many rows). Every field is nullable — an empty profile is valid, since everything is skippable.

**Scoring logic:** tally which `type` number was picked most across all 8 answers. The type with the highest count is the result. Handle ties by picking the first-encountered type among the tied ones (simple, good enough for a self-awareness tool, not a clinical instrument).

```typescript
function scoreEnneagram(answers: Record<string, number>): number {
  const counts: Record<number, number> = {};
  Object.values(answers).forEach((type) => {
    counts[type] = (counts[type] || 0) + 1;
  });
  const sorted = Object.entries(counts).sort((a, b) => b[1] - a[1]);
  return parseInt(sorted[0][0], 10);
}
```

### STEP 3 — Auto-compute Numerology (Life Path Number)

```typescript
export function calculateLifePathNumber(birthDateISO: string): number {
  // birthDateISO format: "YYYY-MM-DD"
  const digits = birthDateISO.replace(/[^0-9]/g, '').split('').map(Number);
  let sum = digits.reduce((a, b) => a + b, 0);

  // Reduce to single digit, except master numbers 11 and 22
  while (sum > 9 && sum !== 11 && sum !== 22) {
    sum = sum.toString().split('').map(Number).reduce((a, b) => a + b, 0);
  }
  return sum;
}
```

### STEP 8 — Serialize the profile into DOST's system prompt (the personalization mechanism)

This is where the profile actually changes DOST's behavior. In your chat edge function, add a function that builds a personalization context block from whatever the user has filled in — gracefully handling any combination of completed/skipped modules.

```typescript
function buildPersonalityContext(profile: PersonalityProfile | null): string {
  if (!profile) return '';

  const parts: string[] = [];

  if (profile.dosha_body || profile.dosha_mind) {
    parts.push(`Constitution (Ayurveda): ${profile.dosha_body || 'unknown'} body, ${profile.dosha_mind || 'unknown'} mind tendency.`);
  }

  if (profile.enneagram_type) {
    parts.push(`Enneagram: Type ${profile.enneagram_type}.`);
  }

  if (profile.life_path_number) {
    parts.push(`Numerology Life Path: ${profile.life_path_number}.`);
  }

  if (profile.tcm_element) {
    parts.push(`TCM dominant element: ${profile.tcm_element}.`);
  }

  if (profile.mbti_type) {
    parts.push(`MBTI: ${profile.mbti_type}.`);
  }

  if (parts.length === 0) return '';

  return `
PERSON'S CONSTITUTIONAL PROFILE (use gently, as subtle context for tone and pacing — never mention these labels directly to the person, never let this override their actual words in this conversation):
${parts.join('\n')}
`;
}
```
